# isudo for iPhone

The approver's side of isudo: it shows exactly what a paired computer wants
to run as root, and signs an approval with a Secure Enclave key behind
Face ID.

- `IsudoKit/` is the logic, with no UI: decoding and checking requests,
  pairing, the display rules, the relay client and the signing keys. It is a
  Swift port of `crates/phone` and `crates/proto`, and its tests check it
  against vectors generated by the Rust code (`testdata/vectors.json`).
- `App/` is the SwiftUI app.
- `project.yml` is the Xcode project, generated with XcodeGen.

## Build and test

```sh
(cd IsudoKit && swift test)   # logic, on the Mac
./build.sh                    # app, for the Simulator (warnings are errors)
./screenshots.sh /tmp/shots   # sample screens, light and dark
./e2e.sh                      # Simulator app + local relay + development isudo
```

`e2e.sh` needs the Rust binaries in `../target/debug`, including a
development build of isudo copied to `isudo-dev`
(`cargo build -p isudo --features dev-unprivileged`).

## Running on a phone

```sh
cp Local.xcconfig.example Local.xcconfig     # then edit it
xcodegen generate
open Isudo.xcodeproj
```

`Local.xcconfig` holds your Apple developer team id and a bundle identifier
you own; it is not tracked by git. Pick your phone as the run destination
and press Run. Xcode creates the signing certificate and profile for you.
The phone needs Developer Mode on, and Face ID or Touch ID set up.

Push notifications need a paid developer membership and an APNs key
configured on the relay (`ISUDO_APNS_*`, with `ISUDO_APNS_TOPIC` equal to
your bundle identifier); without push the app still shows requests while it
is open. On a free account, remove the two entitlements from `project.yml`
or signing will fail.

The app icon is drawn by `tools/make-icon.swift`.

In the Simulator the signing key is a software key, because the Simulator
cannot make Secure Enclave keys bound to biometry. The app says so wherever
that pairing is shown. Device builds do not contain the software key at all:
on a phone without Face ID or Touch ID set up, pairing is refused.

Debug builds accept `-fixture NAME` (`empty`, `quiet`, `plain`, `risky`,
`long`, `multi`, `simulator`, `scan`, `confirm`, `confirmlink`, `waiting`,
`code`, `claimed`, `otherphone`, `steered`, `paired`) and
`-appearance light|dark` to show sample data. Sample data cannot be signed
or sent anywhere.
